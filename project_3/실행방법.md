# BookStore 프로젝트 (boot3 + front3) — 전체 실행 가이드

Spring Boot + Security + JWT + Redis / JPA(MyBatis) + Oracle 백엔드(boot3)와
Next.js + Redux-Saga + Ant Design 프론트엔드(front3)로 구성된 도서/공지사항(Book/Sboard2)
관리 시스템입니다.

---

## 📁 프로젝트 구성

```
boot3/   Spring Boot 백엔드 (REST API)
front3/  Next.js 프론트엔드 (React)
```

---

## 1️⃣ 백엔드(boot3) 실행

### 1) 사전 준비물
- **Oracle DB** (XE 등) 기동
- **Redis** 기동 (세션/캐시용)
- `.env` 파일에 아래 값들이 채워져 있는지 확인

```env
DB_USERNAME=boot
DB_PASSWORD=react

JWT_SECRET=최소64자 이상의 랜덤 문자열

GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...

KAKAO_CLIENT_ID=...        # 소셜로그인 + 도서검색 API 둘 다 이 키 하나로 사용
# KAKAO_REST_API_KEY=...   # (선택) 도서검색 전용 키를 따로 쓰려면 추가

NAVER_CLIENT_ID=...
NAVER_CLIENT_SECRET=...
```

### 2) Oracle DB에 더미 데이터 넣기 (선택이지만 권장)
`dummy_data_book_sboard2.sql` 파일을 SQL*Plus / SQL Developer 등으로 실행합니다.
- 도서 20건, 공지사항 20건이 들어갑니다.
- 테스트용 관리자 계정도 함께 생성됩니다.

```
이메일: admin_test@thejoa703.com
비밀번호: admin1234
```

### 3) 실행

```bash
cd boot3
./gradlew clean bootRun
```

콘솔에 빨간 에러 없이 `Started Boot3Application`이 뜨면 정상입니다.

> ⚠️ 이클립스/STS로 실행하신다면 **Project → Clean...** 을 먼저 한 번 해주세요.
> 예전에 컴파일된 `bin/`, `build/` 폴더가 남아있으면 최신 코드가 아닌
> stale 클래스가 로딩되어 예상치 못한 에러가 날 수 있습니다.

### 4) Swagger로 API 직접 확인

1. `http://localhost:8080/swagger-ui/index.html` 접속
2. `Book Api`, `Notice(Sboard2) Api` 그룹이 보이는지 확인
3. `/api/users/login`에 위 관리자 계정으로 로그인 → JWT 토큰 발급
4. 우측 상단 자물쇠 아이콘에 `Bearer {토큰}` 입력
5. `POST /api/books`, `POST /api/notices`, `POST /api/books/kakao-insert`가
   관리자로는 성공, 로그인 안 하거나 일반회원으로는 403이 뜨는지 확인

## 2️⃣ 프론트엔드(front3) 실행

```bash
cd front3
npm install
npm run dev
```

`http://localhost:3000` 접속 (백엔드가 `http://localhost:8080`에서 떠 있어야 정상 동작합니다)

### 확인해볼 흐름
1. `/login`에서 관리자 계정으로 로그인 (또는 구글/카카오/네이버 소셜로그인 버튼)
2. 상단 메뉴에 `📚 BOOK`, `📢 NOTICE`가 보이고, **관리자로 로그인했을 때만**
   `📘 도서등록`, `📝 공지작성` 메뉴가 추가로 보임
3. `/books` — 12개씩 페이징된 도서 카드 목록, 하단 페이지번호 클릭 이동
4. 헤더 검색창에 도서명 입력 → 실시간 드롭다운 → 클릭하면 **검색키워드 관련 도서 목록** 화면으로 이동
5. `/books/new` — 도서 직접등록 폼 + 하단 "📚 도서 검색 및 등록"(카카오 API 자동등록) 섹션
   - 도서명 입력 후 "검색 및 등록" 클릭 → 카카오에서 가져와 자동 DB저장 → `/books`로 자동이동
6. `/notices` — 12개씩 페이징된 공지사항 테이블, 상세페이지 진입시 조회수 자동 증가
7. 일반회원 계정으로 `/books/new` 직접 접속 → "접근 권한이 없습니다" 카드 화면 확인
   (실제 저장은 백엔드 `@PreAuthorize`가 최종 차단)

## 4️⃣ 구현된 주요 기능 요약

| 영역 | 내용 |
|---|---|
| 인증 | JWT 기반 로그인 + Google/Kakao/Naver 소셜로그인 |
| 권한 | 도서/공지사항 등록·수정·삭제는 `ROLE_ADMIN`만 가능 (`@PreAuthorize` + 프론트 화면단 이중 방어) |
| 도서(Book) | 등록/수정/삭제/상세/검색, 12개씩 페이징, 카카오 도서검색 API 자동등록 |
| 공지사항(Sboard2) | 등록/수정/삭제/상세(조회수 자동증가)/검색, 12개씩 페이징 |
| 데이터저장 | JPA(Hibernate) 기본 + MyBatis 보조 매퍼(BookMapper/Sboard2Mapper) |
| 검색 | 헤더 AJAX 실시간검색 → 검색키워드 관련 도서 목록 화면으로 이동 |
| 문서화 | springdoc-openapi 기반 Swagger UI |

## ⚠️ 막힐 때 체크리스트

| 증상 | 확인할 것 |
|---|---|
| Swagger에 book/notices 안 보임 | 서버 완전 재시작했는지, `/v3/api-docs`에 직접 접속해서 경로 있는지 |
| 도서등록했는데 403 | 로그인한 계정의 `role`이 `ROLE_ADMIN`인지 |
| 관리자인데도 403 | `SecurityConfig.java`에 `@EnableMethodSecurity(prePostEnabled = true)` 있는지 |
| 프론트에서 로그인 안 됨 | 백엔드가 `localhost:8080`에서 떠 있는지, CORS 설정 확인 |
| 카카오 자동등록 401/에러 | `.env`의 `KAKAO_CLIENT_ID`가 카카오 개발자센터 REST API 키와 일치하는지, "도서 검색" API가 앱에 활성화되어 있는지 |
| 화면에서 12개씩 페이징 안 보임 | 도서/공지사항이 13개 이상 등록됐는지 (12개 이하면 페이지번호 자체가 안 뜨는 게 정상) |
| `npm test`/`./gradlew test` 실패 | `npm install`/Oracle DB 기동 여부, 이클립스라면 Clean 후 재시도 |
